### 8-3. 히트마커 + 파편 (`hitMark`, `impactBurst`)
- `fire()`가 히트 좌표를 `screenOf`로 화면에 투영해 `.railHit` 마커를 심는다: 몸샷 흰 ×, 헤드샷 금색 굵은 × + 이중 링 + `HEADSHOT!` 라벨, 킬 적색, 벽 회색, 픽업 녹색.
- `impactBurst(scene, at, kind)`: `concrete`(회백 칩 8 + 먼지 구름 3 + 섬광) / `flesh`(적색 칩 5) / `head`(금·적 칩 11 + 큰 섬광). 기존 `burst()`는 폭발·킬에 그대로.
- 가려진 사격은 `__lastBlocked` 좌표에 벽 마커 + 콘크리트 파편.

### 8-4. 사격 직전 글린트 (`makeGlint`, stepPost의 `warm` 블록)

### 8-6. 세로 화면 아군 보정 (`stepAlly` 앵커)
- 고정 3.3 m 오프셋 대신 **화면 앵커**: `ndc = -0.66(세로)/-0.58(가로)`, `dist` 6.6/6.9 m를 `tanH = tan(vfov/2)·aspect`로 월드 오프셋으로 환산. 390×844에서 아군 NDC x ≈ −0.67, 스케일 0.98 — 조준선(중앙)을 안 가린다.
- 벽 회피는 8-8의 `insideWall`로 앵커가 건물 안에 들어가면 도로 쪽으로 후퇴해 배치.

### 8-7. 움직이는 적 (wave 1)
- **트럭 탑승 사수**: 멤버에 `car: { path, speed, delay }`. `prebuildCovers`가 커버를 만들지 않고, `makePost`가 `makeArmyTruck`을 만들어 벽 목록에 등록. `stepPost` 초반에 트럭이 경로를 따라 주행(세그먼트 보간, 회전 = 진행 방향), 도착하면 `moving = false` + 커버 상태머신 개시. 탑승자는 `y = 1.38`, `coverTop = 1.66`(상반신 노출), 트럭 이동 중엔 `expose = 0`으로 무적.
- **돌격병**: 멤버에 `run: { from, dur, delay }`. `stepPost`의 `run` 블록이 스무스스텝으로 from→dest(원래 커버 자리)를 달리고 `applyRunGait`(아군과 같은 관절 보행: 고관절 스윙·정강이 접힘·팔 펌프·소총 하단 캐리)로 애니. 도착 후 `coverTopSaved` 복원 + 엄폐 상태머신 개시. 달리는 동안 `expose = 1`(몸이 노출 — 맞을 수 있다).
- 두 패턴 모두 명중 판정은 기존 `fire()` 레이캐스트 그대로(움직인 `p.mesh`의 실제 Box3).

### 8-8. 벽 관통 방지 (`rebuildWallBoxes`/`pushOutOfWalls`/`insideWall`)
- `begin()`이 스테이지를 다 지은 뒤 `wallList` + 커버 프롭을 **월드 AABB 배열**로 한 번 정리(77개, 허리 높이 0.45 m 미만 커브/폴/얇은 기둥/전체 블록 배경은 제외).
- `pushOutOfWalls(x, z, r)`: 겹침축 중 가장 얕은 축으로 밀어내기 ×3 반복 — 벽을 따라 미끄러지듯 빠져나온다.
- 아군: 앵커가 벽 안이면 카메라 쪽으로 후퇴해 자리 잡고, 이동 중에도 매 프레임 푸시아웃(`__allyWallNudges`).
- 적: `makePost` 스폰 좌표와 보스 점프 착지 좌표에 동일 적용(커버 프롭도 함께 이동). `__insideWall`로 검증.

### 8-9. 헤드샷 차별화
- **데미지**: 헤드 = 2배(보스 3배). tough(3hp)는 헤드 2발, 보스(8hp)는 헤드 3발 + 몸샷 조합. 점수: 헤드 히트 +75 즉시, 킬 시 +250.
- **연출**: 금색 굵은 × + 팽창 링 + `HEADSHOT!` 라벨 + 금색 파편 + 크로스헤어 금섬광(`#railX.crit`, 0.24 s) + 히트스톱 0.05 s + `GunSFX.crit()`(1,760→3,520 Hz 트라이앵글 팅).
- 판정은 기존 그대로: 명중 y가 히트박스 상단 26% 위면 헤드.

### 8-10. 버추어캅식 `!` 카운트다운 링 (`roleTag`/stepPost 태그 블록)
- `.railThreat`가 적 몸통 중심에 그려지는 **원형 링**: 지름은 화면에서 본 적 키의 1.55배(44~260 px 클램프).
- `conic-gradient(--p)`가 남은 시간, `--c`가 3단계: 초록(peek/사격 초반, 여유) → 주황(k 0.35~0.72) → 빨강 점멸 + 스케일 펄스(0.72~1.0, 발사 직전). 링 위 눈금(ticks)과 남은 시각 위치에 빨간 삼각형 화살표가 링을 따라 회전.
- 태그 안쪽 `b`가 기존 `!` 뱃지(색은 단계 따라감). glint(8-4)와 함께 "언제 쏘는지"가 두 겺로 보인다.

### 8-11. 성능 (1280×720, headless SwiftShader 측정 — 실기기 GPU와는 무관)
- draw call **약 1,050**(세로 390×844 약 800), 삼각형 **약 13,700**(세로 약 10,200), 텍스처 83장, 지오메트리 약 1,330. v7 대비 +140 call(서울 소품/간판 분) — 삼각형 자체는 가볍고(1.4만) 실기기 GPU에서 여유. 구름 박스 3개로 축소, 옥상 에어컨 2개로 축소.
- **프레임 측정 주의**: headless SwiftShader는 소프트웨어 렌더라 FPS 수치(가로 약 2.4, 세로 약 5.8)는 의미가 없다. 삼각형·드로우콜 수치로 판단할 것.

### 8-12. Stage 2+ 확장 메모 (헬기·낙하산 공중 적 — 이번 PR 미포함, 사용자 확정)
- `WAVE_DEFS` 멤버에 `air: { kind: "heli"|"chute", ... }`를 허용하도록 `roleOf`/`makePost`를 넓히면 된다. `makePost`는 `elev`로 이미 고도를 지원하고, `posePost`/`fire()` 판정은 `p.mesh` Box3라 공중 표적도 그대로 동작.

## 2-1. 이번 라운드 (v10) — 텍스처 · 그래픽 강화

사용자 지시: *"텍스처 강화 그래픽 강화"*. 게임플레이(서울 배경 구성, 버추어캅 `!` 링, 헤드샷 배율, 벽 관통 77 콜라이더, 트럭/돌격병, 태극기 양면, PC/세로 조작)는 **그대로 두고 표면만** 끌어올렸다.

### 10-1. 재질 계열: Lambert → MeshStandard
- `makeSol()`의 `L()`이 이제 `MeshStandardMaterial`을 만든다. `roughness`/`metalness`를 재질별로 지정했고, 재질 이름(키)은 하나도 바뀌지 않아 나머지 코드는 그대로 붙는다.
- 대표값: 아스팔트 0.84 / 콘크리트 0.90~0.93 / 석조 0.80~0.86 / 유리 0.07~0.22+metalness 0.4~0.55 / 강철·크롬 0.24~0.34+metalness 0.88~0.96 / 천(위장·전투복) 0.90~0.93 / 자동차 도장 0.30~0.38 / 총몸 블루스틸 0.26+metalness 0.92.
- 파생 코드도 같이 바꿨다: `faceMat`(얼굴), `signMat`(간판), 도로표지, `darkMat`, 바리케이드 패널, 스캐폴드 그물, 지면 Plane, **권총 뷰모델 전체**(`mk`/`mm`/`gripMat`/소매 `cloth`).

### 10-2. 범프·러프니스 맵 생성기
- `bumpTex(key, src, opt)`: 컬러 캔버스의 휘도를 그대로 높이맵으로 쓴다(1회 3×3 박스 블러 + `gain` 대비, 256², 선형 인코딩). `ctex`가 `TXCV[key]`에 원본 캔버스를 남기고 텍스처에 `__key`를 달아 두므로 `BM("콘크리트키", gain)` 한 줄로 붙는다.
- `roughTex(key, draw, opt)`: 반사가 다른 면을 직접 칠한다(파사드 유리=거의 거울, 창틀=중간, 스팬드럴=무광).
- `grain(g,w,h,amount,seed)`: 픽셀 단위 노이즈. 1024² 도로가 "사각 타일 패턴"으로 보이던 문제를 없앴다.
- 텍스처 메모리는 `bumpTex` 256², `roughTex` 128²로 묶어 총 126장(기존 83장) — 증가분 대부분이 높이/러프니스 맵이다.

### 10-3. 표면 텍스처 강화
- **아스팔트**(`asphaltTex`, 768² 지면/1024² 기본): 더 어두운 비튜멘 베이스 + 재포장 패치(직선 경계·다른 톤) + 타이어가 닦은 두 줄 광 + 타르 시임 + 분기 균열 + 유막/오일 얼룩 + 1.1만개 골재 + 픽셀 그레인.
- **보도블록**(`paveTex`): 4분할 격자 유지, 줄눈에 흙·이끼, 모서리 파손, 비에 젖은 얼룩, 껌.
- **콘크리트**(`concreteTex`): 빗물 세로 얼룩 + 백화(석회 번짐) 추가 — 방호벽이 "새 것"처럼 보이지 않는다.
- **도로 페인트**(`paintTex`): 차선·횡단보도가 균열/마모된 도료로 보이게. `paintBar`가 `repMat`으로 타일링.
- **타이어**(`treadTex`): 스태거 블록 트레드 + 범프(버스·경찰차·트럭 바퀴 공용).
- **수목**(`folTex`): 나뭇잎 다발 텍스처 — 초록 박스가 덤불로 읽힌다(`SOL.hedge`).
- 석조(`blockTex`)·기와(`roofTileTex`)·목재는 기존 그림에 범프만 얹었다.

### 10-4. 유리 커튼월 파사드 재작성 (`facadeTex`, 384 → 512)
- 창마다 **리빌**(어두운 홈 + 햇빛 쪽 밝은 모서리 + 씰 그림자) → 창이 포스터가 아니라 구멍으로 읽힌다.
- 유리: 위는 하늘, 아래는 도시가 반사되는 그라데이션 + 비스듬한 글레어 + 건너편 블록이 비치는 어두운 띠.
- 실내: 켜진 사무실(천장 조명·책상 라인) 11%, 블라인드 30%(슬랫 간격·아래 그림자), 화분/책상 실루엣.
- 창틀 중앙 멀리언에 하이라이트, 창턱 밝은 선 + 그 아래 하드 섀도, 필라스터 좌우 명암, 파라펫 낙영.
- 유리/창틀/벽의 러프니스 맵을 함께 생성 → 유리에만 환경 반사가 산다.

### 10-5. 환경맵(반사)
- `buildSceneEnv(ctx)`: 512×256 등장방형 파노라마(하늘·태양 플레어·구름·도시 스카이라인·노면)를 `PMREMGenerator`로 1회 프리필터 → `scene.environment`.
- 부팅 1회 비용만 들고 프레임 비용은 없다. 유리·크롬 허브캡·경찰차 창·권총 슬라이드가 같은 하늘을 반사한다.
- `envMapIntensity` 기본 0.18(난반사), 유리 0.6~0.9, 금속 0.7로 낮게 잡아 씻겨 보이지 않게 했다.

### 10-6. 조명 · 톤매핑 · 그림자
- `ACESFilmicToneMapping` + `toneMappingExposure 1.12`, `PCFSoftShadowMap`, 그림자 맵 **2048²**, `normalBias 0.03`, `bias -0.0004`, 프러스텀 ±46/52/-40(far 190)로 좁혀 텍셀을 교전 반경에 몰아줬다.
- **`key.shadow.camera.updateProjectionMatrix()`를 반드시 호출**한다(엔진 초기화). r128은 프러스텀 값을 바꿔도 재계산을 해 주지 않아, 이걸 빼면 그림자가 통째로 사라진다.
- 태양을 낮은 남서 방향(`SUN = [32,22,14]`, 카메라 기준 상대 오프셋)으로 내려 건물 그림자가 도로를 비스듬히 가로지른다. 디버그용으로 `window.__mgSun = [x,y,z]`로 즉시 바꿀 수 있다.
- 안개 `Fog(0xd6e6f2, 130, 460)` — 숭례문·남산이 거리로 읽히되 뿌옇게 죽지 않는 지점.

### 10-7. 오브젝트 디테일
- 권총: 슬라이드/프레임/그립 재질 분리(블루스틸 0.26·폴리머 0.50·체커 그립 0.62), 전·후방 조준기 도트를 **자발광(emissive)** 으로 — 그늘에서도 보인다.
- 차량: 트레드 범프, 크롬 허브캡(0.95 metal), 경찰차/버스 도장 클리어코트 느낌, `carGlass` 거울 반사, 헤드램프/경광등 기본 발광 유지.
- 캐릭터: 디지털 군복·헬멧(0.44)·장구류 범프, 얼굴 재질 표준화.

### 10-8. 전투 이펙트
- **총구 화염**: 기존 노란 박스 위에 4방향 화염 스타 텍스처를 교차 카드 2장(가산 혼합, depthTest off)으로 얹었다. `fire()`가 켜고 `frame()`이 80 ms 동안 키우며 페이드.

- 피격 파편·연기·트레이서는 기존 로직 그대로.

## 2-2. 병합 메모 (v10 표면 + Stage 2, PR #12)

두 갈래 작업이 같은 `rail.js`를 각각 고쳐 충돌 4곳이 났고, 다음과 같이 합쳤다.

- **`!` 위협 마커**: Stage 2의 `placeTag()`(지상병·헬기 사수·낙하산·장갑차 공용, `--rtp`/`--rtc` conic 링)를 남기고 v9의 몸통 크기 링 CSS는 쓰지 않았다. v9의 **사격 직전 글린트**(`makeGlint`, 0.55초 전 붉은 총구 섬광 + 조준 레이저)는 그대로 살려 `posePost`에서 `placeTag` 바로 앞에 둔다.
- **헤드샷 피해량**: Stage 2 쪽 식(`head ? boss?3:2 : 1`, `window.__lastDmg` 계측 포함)을 채택.
- **이름 충돌**: v10의 `bumpTex(key, src, opt)`(컬러 캔버스에서 높이맵 유도)와 Stage 2의 `bumpTex(key, size, seed, amp)`(노이즈)가 같은 이름이었다. JS는 나중 선언이 이기므로 Stage 2 것을 **`bumpNoise()`** 로 바꾸고 호출 9곳을 함께 고쳤다.
- **달리는 적 두 규격 공존**: Stage 1은 `run: { from, dur }`(v9), Stage 2는 `run: true, route: [...]`(v8). `makePost`·`posePost`에서 `m.run.from`/`p.run.from`이 있을 때만 v9 경로를 타게 가드해, Stage 2 돌격병이 `p.run.dest`를 읽다 죽던 `frameErr`를 없앴다.
- **스테이지 배경**: `dressBattlefield()`가 스테이지에 따라 `dressStage1`(서울) / `dressStage2`(DMZ·JSA)로 분기하고, `dressStage1` 본문은 v10의 서울 리뉴얼을 그대로 쓴다.
- 캐시 버스터는 라이브가 `?v=9`였으므로 `?v=10`으로 올렸다(이 값이 새 빌드를 확실히 다시 받게 한다).

### 3-4. 신규 적 기믹 (모두 기존 `foe` 히트박스·`!` 예고·헤드샷 규격 위에서 동작)

## 4. 이전 라운드 (v7) — 보이는 만큼만 맞는다 · 적 사격 모션 · 아군 걷기 · 캐릭터 디테일 · 태극기


사용자 제보: *"렌더링 시점이 제각각이라 적이 숨어있는 벽이 나중에 갑자기 생겨남"*, *"적이 가만히 서있는 것 같음, 총쏘는 모션"*, *"숨어있는데 다 보이고, 쏘면 명중으로 인정 안 됨"*, *"컴퓨터로 R 누르면 재장전"*, *"아군이 미끄러져감"*, *"캐릭터 디테일"*, *"태극기가 가짜"*.

### 4-1. 엄폐물이 플레이어 쪽을 향하게 (팝인 + "다 보임"의 뿌리)
- **원인 1**: `buildCover()`가 가림막을 **웨이브의 진행축(+z)** 기준 0.95 m 앞에 놓았다. 그런데 플레이어는 `hold` 지점에서 보고, 옆으로 띄운 적(`lat -9.4` 등)은 시선이 진행축에서 최대 58° 벌어진다. 그래서 가림막이 적의 **옆**에 서고 적은 통째로 노출됐다.
  → `coverPlace()`가 **hold → 적** 선 위 0.95 m에 가림막을 놓고 `rotation.y`도 그 선에 수직으로 맞춘다. 적은 이제 항상 자기 가림막 뒤에 있다.
- **원인 2**: 가림막을 `startWave()`에서 만들었다. 카메라가 도착한 그 프레임에 눈앞 5~15 m에 샌드백이 **툭 튀어나왔다**.
  → `prebuildCovers()`가 `begin()`에서 **4개 웨이브 + 보스의 가림막 22개를 전부** 만든다. 맵을 도는 동안 벽은 늘 그 자리에 있다.
- **적도 미리 세운다**: `stageWave()`가 이전 웨이브를 끝낼 때 다음 구역의 병사를 미리 배치한다(1웨이브는 `begin()`에서). 그들은 가림막 뒤에 숙인 자세로 서 있고, 도착하는 순간 `startWave()`가 `live = true`로 전투만 시작한다. `p.live === false`인 병사는 `stepPost`·`livingHostiles`·조준 보조·피격 목록에서 빠진다.
- 42 m 이상 떨어진 구역의 가림막 그룹은 `visible = false`(draw call 절감). 40 m 넘게 떨어진 곳에서 사라지는 건 눈에 띄지 않는다.

### 4-2. 숨어 있으면 안 보이고, 보이면 맞는다 (핵심 버그)
- **원인**: `startWave()`가 `squashY = (coverHeight(종류) - 0.06) / headTop`로 몸을 눌렀는데, `coverHeight()`는 **실제 프롭 높이와 다른 표**였다(샌드백 실제 0.99 m vs 표 1.10, 문틀 실제 1.65 m vs 표 1.62, 높은 데 올라간 적은 더 벌어짐). 그래서 머리·어깨가 가림막 위로 5~35 cm씩 튀어나왔다. 동시에 `fire()`는 `p.expose > 0.42`인 적만 목록에 넣어서 **보이는 그 머리에는 판정이 없었다**. → "보이는데 안 맞음".
- **가림막 높이는 이제 잰다**: `buildCover()`가 만든 그룹의 `Box3`에서 `topY`·중심을 저장하고, 병사 모델도 생성 직후 `Box3`로 실제 키(`headTop`)를 잰다.
- **시선으로 숙인다**: `posePost()`가 매 프레임 `hideTop = coverTop + (카메라높이 - coverTop) · (d적 - d가림막)/d가림막`을 구해, **카메라에서 실제로 보이기 시작하는 높이**를 계산하고 몸을 그 높이까지만 남긴다(`hideFrac`). 카메라가 가까워지면 눈높이 때문에 더 숙고, 멀면 덜 숙는다. 노출(`expose`)이 오르면 그대로 일어선다(`sy = hideFrac + (1-hideFrac)·expose`).
- **판정은 기하가 한다**: `fire()`가 이제 (a) **살아 있는 모든 적**(엄폐/노출 무관) + (b) 탄약·기름통 + **(c) 가림막·건물 벽**을 같은 레이에 넣고 **가장 가까운 것**으로 결과를 정한다. 벽/가림막이 먼저 맞으면 빗나감(샌드백에 불꽃)이고, 적이 먼저 맞으면 명중이다. 즉 **보이는 실루엣 = 맞는 실루엣**.
- 벽 태그: `blockAt()`·`roofCap()`·`balcony()` 난간·성문 교각에 `userData.wall = 1`을 붙여 `wallList`로 모은다. 픽셀 보조 판정도 벽에 가로막힌 점은 건너뛴다.
- 보스는 무거운 바리케이드 3개 사이를 옮겨 다니며, 이동할 때 `coverG`/`coverTop`도 그 바리케이드로 바뀐다.

### 4-3. 적 사격 모션 (가만히 서 있던 문제)
- 병사 리그에 **어깨 관절(양팔)·고관절(양다리, 정강이 별도)**을 넣었다. 상태에 따라 `armK`(0=숙임, 1=견착)가 부드럽게 오가며 팔·소총 자세가 바뀐다: 숙임=소총 아래로, 피크=들어올리는 중, 사격=견착 후 반동.
- 사격: `stateT`/`aim`이 0이 되면 `burstN = 2`(tough·boss 3)점사. 점사마다 **총구 화염(구체+파편 4개)·카메라로 오는 예광탄(카메라 5 m 앞에서 끊는다)·소총 반동·`GunSFX.rifle()`** 이 발생하고, **첫 발에만 피해**가 들어간다(한 번의 공격 = 기존과 같은 피해량).
- 몸통 호흡(`breath`), 머리 미세 흔들림, 다리 스탠스 변화로 가만히 있어도 살아 있어 보인다.
- 총구 위치는 소총에 붙인 `userData.muzzle`(총열 끝 0.75 m)이다.

### 4-4. R 재장전
- 원래도 `keydown`에서 `e.code === "KeyR"`로 걸려 있었고 headless Chromium에서 **17발 → R → 20발**로 동작을 확인했다. 이번에 보강: `Ctrl/Meta/Alt` 조합은 무시, `INPUT/TEXTAREA/contentEditable`에서는 무시, `e.key.toLowerCase() === "r"`·한글 자판(`ㄱ`)도 인식, `e.repeat`(꾹 누름)은 한 번만, `preventDefault()`로 브라우저 단축키에 새지 않게.

### 4-5. 아군 걷기 (미끄러지던 문제)
- `makeAlly()`를 무릎 꿇린 정지 자세에서 **선 자세 + 관절 리그**로 다시 만들었다.
- `stepAlly()`가 **실제로 이동한 거리**로 보행 위상을 돌린다(`phase += 이동거리 · 2.6`): 허벅지 ±0.52 rad 스윙, 정강이 굽힘, 팔 카운터 스윙, 발딛을 때 몸통 바운스(`|sin|·0.05`), 좌우 롤. 멈추면 `aimK`가 올라가 **사격 자세**(다리 굽히고 몸 낮추고 소총 견착)로 전환한다.
- 예광탄 시작점은 총구(`userData.muzzle`), 발사 시 반동 0.18 rad.

## 5. 이전 라운드 (v6) — 세로 화면 팔·몸통·화각 + 총구 조준

사용자가 아이폰 세로 화면(390×844) 스크린샷에서 지적한 것들: 손목 커프가 허공에 뜸, 좌우 적이 잘림, 총구가 조준 방향을 안 따라감.

### 4-1. 1인칭 팔·몸통 전체 (`makePistol()`)
- 예전 뷰모델은 손 아래 위장 소매 블록 4개가 전부였다. 세로 화면은 손 아래로 0.3 m 넘게 보여서 커프가 화면 가운데에 떠 있었다.
- 이제 `손목 → 소매 커프 → 팔뚝 → 팔꿈치 → 위팔 → 어깨(견갑) → 멜빵/조끼 → 몸통`이 끊기지 않는 사슬로 이어지고, 마지막 마디는 화면 아래·옆 **밖으로** 빠져나간다.
- 소매는 상자 대신 **육각기둥**(`CylinderGeometry`, 6·8각). 위에서 내려다볼 때 널빤지가 아니라 천으로 감싼 팔처럼 보인다. 위장 텍스처는 마디 길이에 맞춰 반복을 계산해 늘어나지 않는다(`cloth()`).
- **두 그룹 분리**: `aim`(권총·양손·양 팔뚝·팔꿈치) 은 **오른팔 팔꿈치 축**으로 돌고, `body`(위팔·어깨·조끼·몸통) 는 몸통에 붙어 있다. 조준으로 팔이 크게 돌아도 오른 어깨는 팔꿈치가 축이라 벌어지지 않고, 왼쪽 위팔은 매 프레임 `어깨 → (움직인) 팔꿈치`로 다시 맞춘다(길이만 살짝 늘어남).
- 검증용 표식: 마지막 마디 메시에 `userData.armEnd = 1`.

### 4-2. 세로 화면 가로 화각 유지 (`viewFov()`)
- `camera.fov`는 **세로** 각도다. 세로 화면에서 58~60°를 그대로 쓰면 가로 화각이 **29.9°**까지 줄어 좌우 적이 화면 밖으로 밀린다.
- 세로(`aspect < 1`)에서는 `vfov = 2·atan(tan(76°/2) / aspect)` 로 가로 76°를 유지하려 하고 **52~82°로 클램프**. 390×844 → `vfov 82°` → 가로 **43.8°**(+47%).
- `aspect`가 1에 가까워지면 58°로 부드럽게 수렴(회전 시 튐 없음). 가로(`aspect >= 1`)는 기존 58° 그대로.
- 적 좌우 배치 한계(`halfTan()`)도 같은 함수를 쓰므로 화각을 바꾸면 적 배치 폭도 같이 바뀐다.

### 4-3. 뷰모델 위치·크기 (프레임 루프)
- 세로에서는 리그를 `0.13·(1-aspect)` 만큼 아래로 내리고, `1 + 0.8·(1-aspect)` 만큼 키운다(390×844: scale 0.154 → **0.22**, y −0.303). 가로는 기존 값 그대로.

### 4-4. 총구가 조준점을 따라감
- `fire()`가 쓰는 것과 **같은 조준 레이**로 목표점을 잡는다: 레이 위에 노출된 적이 있으면 그 가슴(2.5~34 m), 없으면 레이 26 m 지점.
- 발사해서 명중하면 그 **실제 명중 좌표**(`hit.at`)를 140 ms 동안 목표로 삼아 총구가 그 점으로 스냅한다.
- 총구는 팔꿈치 축보다 0.77 위에 떠 있으므로, 목표 방향을 **총구 위치에서 다시 계산하는 2회 반복**으로 풀어 총열 선이 목표를 실제로 지나가게 한다.
- 각도는 `yaw ±0.52 rad(±30°)`, `pitch −0.30~+0.42 rad` 로 클램프(어깨가 따라갈 수 있는 범위). 12/s 슬레프로 부드럽게 추종, 발사 순간만 즉시 스냅. 반동은 조준 회전 위에 x축으로 더한다.
- 실측: 조준점을 화면 왼쪽 끝(6%, 42%)으로 옮기면 `yaw 0.352 rad`, **총열 방향과 총구→목표 방향의 오차 0.55°**(26 m에서 0.25 m). 가운데 0.84°, 오른쪽 0.59°.

## 6-9. v14 — 오브젝트 겹침·관통 정리 (2026-11-22)

사용자 제보(스크린샷 3장): 성문 지붕이 서로 뚫고 나옴, 콘이 공사중 벽에 박힘, 바닥이 갈색 픽셀로 덮임.

- **가게 전면이 45°로 서 있던 버그** (`streetFront`): `o.az || 1`이 명시적 0을 1로 바꿔 동·서향 가게 전면(유리·간판·차양) 전부가 45° 돌아 건물과 도로를 대각선으로 관통하고 있었다. `!= null` 기본값으로 수정. (레일 차단물에 잡히던 25 m짜리 "대각선 판"도 이것.)
- **성문 지붕** (`makeKoreanGate`): 기둥 중간을 자르던 아래 지붕 + 기울어진 4각뿔 면이 서로 뚫고 나오던 2단 지붕 → 단청 위에 얹힌 팔작지붕 1개(서까래 + 넓은 처마 + 들린 모서리 + 기와 단 + 용마루). 태극기는 지붕 밖, 석축 앞 모서리로. 현판은 플레이어 쪽 면.
- **아군이 카메라에 붙던 문제** (`stepAlly`) — 스크린샷 3의 갈색 픽셀 바닥과 왼쪽 검은 덩어리의 정체: 자리가 벽 안이면 카메라 쪽으로 끝까지 당겨 와 화면 아래를 위장복이 덮었다. 이제 왼쪽(최대 55 %까지만 당김) → 오른쪽 → 조금 앞 순서로 빈자리를 찾고, 카메라와 3 m 이상 유지, 2 m 안이면 숨김(`window.__allyDist`).
- **배치 수정**: 버스(가게 전면에 꼬리가 박혀 있던 것)를 연석 따라 평행 주차, 경찰차 2대 위치 조정, 가로수 1그루 이동, 콘 이동, 저지 1개 제거. Stage 2: 트럭 2대가 파란 막사 안에 있던 것 밖으로, 낡은 평면 초록 상자 나무 48그루 삭제(복셀 숲으로 대체), 복셀 숲은 이미 선 구조물 2.2 m 밖에만 심음. 스카이라인 빌딩끼리 간격 유지.
- **`declutter()`**: 엄폐물·차량 안에 놓인 작은 소품(콘·소화전·화분·상자)은 숨긴다(드럼통 제외, `window.__declutter`).

## 11. 구조 메모 (다음에 손댈 때)

- **텍스처**: `ctex(key, w, h, draw)`가 캐시. 512(바닥·석조·목재·조약돌)·256(천·위장복·금속·가죽·얼굴)·128(헬멧·폴리머). 큰 박스는 `tiledMat()`(타일 1장 = 2.4 m).
- **이방성**: `MAXANISO`는 `begin()`에서 GPU 값(최대 8). 새 텍스처는 반드시 `ctex` 경유.
- **화각**: `viewFov()` 하나만 고치면 된다. 세로에서 가로 76° 유지 → 52~82° 클램프.
- **뷰모델**: `makePistol()`이 `g`(위치·스케일) 아래 `aim`(회전·조준)과 `body`(고정)를 만든다. 총·손 위치를 바꾸면 `pistolPivot`(오른팔 팔꿈치)과 왼팔 재맞춤 좌표(프레임 루프의 `tmpV.set(-0.366,-0.705,0.405)`, `tmpT3.set(-0.575,-1.1,0.78)`)도 같이 고쳐야 한다.
- **조준 목표**: 프레임 루프의 `---- point the barrel ----` 블록.
- **사망 연출**: `killPost()`가 `p.fall = {dir, spin, push, kx/kz, lean, side}`, `---- dying ----` 블록이 소비.
- **육성**: `GunSFX.playHitGrunt(fatal)` 하나만 호출(`grunt(fatal)` 래퍼 경유).
- **웨이브**: `WAVE_DEFS`(hold/yaw/look/time/members/picks). 멤버는 `{role, lat, dep, elev, cover}`, `cover`는 `sandbag|crate|crates|barrier|bunker|door|truckbed|heavy|rail`.
- **가림막**: `coverPlace(w,m,i)`가 **hold→적** 선 위 0.95 m에 놓고 `buildCover()`가 실제 `Box3`로 `userData.topY`·중심을 기록한다. `prebuildCovers()`가 `begin()`에서 각 웨이브의 `coverGroup`에 전부 만든다. 높이표 `coverHeight()`는 이제 'rail'(발코니 난간) 폴백에만 쓴다.
- **엄폐/노출**: `makePost()`가 병사를 만들고(모델 `Box3`로 `headTop` 측정), `stageWave()`가 미리 세우며, `startWave()`가 `live = true`로 깨운다. 매 프레임 `posePost()`가 `hideFrac`(시선 기준으로 숙는 정도) → `sy` → `body.scale.y`를 정하고 `p.visTop`을 남긴다. **판정은 `fire()`의 레이캐스트가 가림막·벽까지 포함해 가장 가까운 것으로 결정**한다. 엄폐 여부를 `expose` 플래그로 판정하지 말 것.
- **벽 태그**: `blockAt()`·`roofCap()`·`balcony()` 난간·성문 교각에 `userData.wall = 1`. `wallList`는 `begin()`에서 `dress.root`를 순회해 모은다.
- **적 사격**: `stepPost()`의 `fire` 상태가 점사(`burstN`)를 돌리고 `enemyFire()`가 총구 화염·예광탄·`GunSFX.rifle()`·피해(첫 발만)를 낸다. 총구는 `userData.muzzle`.
- **아군**: `makeAlly()`가 선 자세 관절 리그, `stepAlly()`가 이동 거리 기반 보행(`userData.phase`)과 사격 자세(`aimK`)를 섞는다.
- **태극기**: `flagKR()` — 공식 작도. 크기·비율을 바꾸려면 `ctex("flagKR", 384, 256, ...)`의 두 수만 3:2로 유지.
- **경로**: `PATH_PTS`(x,z) 스플라인. 정지점은 각 `hold`에 가장 가까운 경로점으로 스냅.
- **재시작**: `RAIL.begin(ctx)`가 코스·웨이브·픽업·가림막을 지우고 다시 짓는다(`clearStage` → `buildWaves`/`buildPickups`/`dressBattlefield`). 뷰모델은 `boot()`에서 한 번만 만든다.
